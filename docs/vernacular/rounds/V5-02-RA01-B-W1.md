## Dispatch (coordinator, 2026-10-30)

### Objective

Implement the structural half of RA01 exactly as [authoring-contract.md](../authoring-contract.md) (RA-1, RA-9, Common rules,
Messages) and [execution-design.md](../execution-design.md#5-split-waves-and-size) section 5 define it: the six authoring and driver

mapping and the six root-help lines, all with stub handlers. Stubs never produce prompts, observations or projections.

Binding reading of the contract (plan review must confirm, no operator question is open): RA-1 says the public default catalog
and root help stay at five rows and five families until the integrated RA01 gate (RA01-C), and that intermediate runtime
support may use test-only eleven-row bundles and must not expose a partially working public verb. So wave 1 builds and tests the
eleven-row validator, the eleven-line help generator and the six CLI families, selectable only by test-only bundles and test
harness entry points. The production binary's default catalog, root help bytes and `--help` output stay byte-identical to HEAD
until RA01-C flips them. If search finds that the contract cannot be implemented this way, it must halt with the question,
options and a recommendation instead of choosing.
