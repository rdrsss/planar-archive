# V5-02-X06-B3-C: native v2 derivation and `prepared_profile`

## Dispatch (2026-10-25)

### Objective

Deliver phase steps 4 to 6 of the "Authentic runtime preparation" row in
[the preparation architecture](../profile-preparation-architecture.md#preparation-phases-native-derivation-and-retained-authority).
B3-B (commit `7110196d`) left a consumed owner inside the private, non-published
`profile_load_stage`, which holds the sealed capture, the normalized bundle B and the
final model S. This round turns that stage into the opaque, move-only
`prepared_profile`:

1. Assemble the exact effective raw tree from the owner's own original module and
   profile bytes, catalog, owner annotations and shipped sources, and verify its
   membership, modes, order and catalog with `effective_provenance`.
2. Call the existing pure `encode_interpretation_v2` on the private B, S and raw tree,
   and derive E, V, the tagged selected definitions and the raw stdlib digest natively.
   Nothing from Lua or a caller is accepted as a version, digest, record or receipt.
3. Verify B and S identities, workspace ID and source correspondence with the shared
   load logic, derive the sorted source tree and digest from the sealed capture, and
   build an immutable `profile_acceptance_data` privately.
4. Verify all original receipts, mark the invocation consumed before any fallible
   outward copy, and move the profile capture, acceptance capture and dormant VM and
   accounting into `prepared_profile`. Expose `data()`, `bound_intent()` and
   `verify_native_receipts()` as fixed methods that grant no construction authority.

Out of scope: any transaction or ledger change (`complete_profile_acceptance`), CLI
or init cutover, whole-invocation budgets, and the fresh profile acceptance refusal,
which must stay. `prepare_load` returns `prepared_profile` instead of the stage;
the stage type may stay as an internal step but gains no public accessor.

### Dependencies

### Acceptance criteria

1. A real selected profile with a built-in and custom job mix prepares successfully;
   `data()` carries source tree and digest, registry, verified effective tree, v2
   interpretation and versions, workspace ID and exact bound intent. Interpretation
   and versions bytes equal the embedded derivation for the same inputs (separate V
   byte-equals embedded V). Bounds are 16 MiB each.
2. No caller path constructs or upgrades a prepared object: no API accepts a caller
   bundle, model, raw tree, digest or encoded record; opaque, consumed and failed
   owners publish nothing; `data()` copies cannot be fed back as authority; the
   prepared type is move-only with no public constructor.
3. Failure order: receipts are verified before publication; a source, registry or
   profile file replaced after prepare-start but before publication refuses and
   publishes nothing. `verify_native_receipts()` returns the first concrete native
   failure, runs no Lua, admits no new file and retries nothing, and fails after
   replacement of the selected declaration, a closure member, the registry and the
   profile after publication.
4. The invocation is marked consumed before any fallible copy, including on
   `bad_alloc` and encoder failure; a final catch maps unexpected exceptions to a
   protocol failure (carried advisory X06B3B-N5); derivation work is charged to the
   same single frame, with no counter reset.
5. Carried B3-B lessons. (a) The zero-declaration-read check at
   `runtime.t.cpp:1528-1539` (opaque adoption, `planar_admission_read_attempts() == 0`)
   cannot fail, because the interposer watches only one inode and the opaque owner
   never opens a declaration. Since this round extends the same area, replace it with
   a check that can fail, for example a known-load owner whose declaration is read
   through the watched path and observed as at least one read, paired with the
   opaque zero-read assertion; if it cannot be made falsifiable, record the limit
   with the reason. The existing test name is kept. (b) Do not add observation-only
   fields or methods to public product types; the N-c amendment covers `owner_charge`
   only. Use same-module test observation, and report any unobservable behaviour as a
   limit. (c) Any probe survivor that cannot be reached must be recorded with a reason.
   (d) Carried advisories X06B3B-N1 (charge before allocating; test that detects
   removal), N3 (probe sets cite the "D2 B2 C01 first retained reads require original
   root selection" test), N4 (list unreachable refusal branches with reasons) and N6
   (no PENDING verification entries) are resolved or recorded with a reason.
6. All 987 current test names are preserved; existing diagnostic messages are
   byte-identical; no runtime `assert()` validation; typed `std::expected` failures;
   module documentation rules followed; public CLI and fresh profile acceptance
   refusal are unchanged; the dependency audit shows no cycle.
7. Every new test can fail. The coder describes which mutant each new test kills.
   Only the mutation prober applies mutants, in a scratch copy outside the checkout,
   covering at least: skipped receipt verification before publication, consumed mark
   after copy, tree assembled from caller or wrong bytes, wrong digest or version
   source, counter reset, `verify_native_receipts` skipping the selected declaration
   or registry, and `data()` exposing mutable state. Raw logs name the killing test
   and show restored hashes. Red-first evidence is behavioural, with the exact
   command and a hash of the pre-fix snapshot.
