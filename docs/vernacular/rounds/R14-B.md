## Search, contract reading and bounded sequence

Fresh `/root/r14b_search` confirmed all open/write/commit/backup/restore/recovery
paths converge through private `verify(connection&)`. Split B1 pure bounded
event/result JSON codecs from B2 streaming chronology/request/projection and
referenced-content validation. B1 leaves populated history refused; B2 integrates
all required layers before allowing it. Fresh subround searches precede coding.

Result `parent` describes the returned `revision` row's `parent_id`, including
no-op. A no-op returns an existing revision and its existing parent; event
before/after fields separately describe the operation's unchanged head. This
clarifies the normal revision-field meaning without inventing lineage on no-op.
Pin this interpretation in codecs, cross-link fixtures and later acceptance.

Only event sequences carry the explicit gap-free validation requirement.
Record IDs retain approved positive signed-64 and older-child rules (including
existing maximum-ID tests with gaps). Revision acceptance is chronological:
initial accepted revision is 1, subsequent accepted IDs increase and parent is
the immediately previous active revision. Do not add a gap-free invariant for
all record IDs. Native allocation still uses guarded MAX+1; no allocator policy
changes. Timestamps have the existing UTC-millisecond syntax and are context,
not causal order; never reject valid history merely because clocks moved back.

Unsupported interpretation versions within the supported canonical payload are
allowed only after fixed envelope/shape/separate-version integrity checks; raw
source remains readable, while interpreted reads report unsupported. Unsupported
record framing or payload codec is not silently accepted. Deep verification can
read bounded canonical metadata after the pure decoder reports well-shaped
unsupported_version; it does not execute modern Lua or waive workspace/stdlib
reference checks. Exact stdlib manifest verification remains required for this
format's supported provenance representation.

B1 codec DTOs will be inert, storage-independent values; B2 owns all SQL/cross-row
checks and reuses the existing typed record reader via explicit local callbacks.
Forced-digest format tests remain record-only; do not redefine real provenance
hash semantics to admit fabricated accepted-history trees in a test variant.
