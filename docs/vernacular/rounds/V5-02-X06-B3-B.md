## Decisions

- The stage type `profile_load_stage` is an opaque move-only handle whose only member is
  `observe()`. It has no accessor for B, S or the capture and no route to any transaction API.
- The error type is `profile_preparation_error{registration_error failure; value_ptr semantic}`.
- `begin_frame` is now private static; the owner opens exactly one frame.
- `prepare_load` moves the owner implementation out before any fallible copy
  (consumed-first), so failed or consumed owners never retry and publish nothing.
- Known-load `into_extension` is refused (X06B3A-N3). Reason: adopting a known-load owner
  would change its mode after load binding, which the architecture forbids.
- X06B3A-N4: charge `sizeof(implementation) + 64` per owner and
  `sizeof(stage implementation) + 64` per stage, cumulative, with no refund.
- X06B3AC02-N3 resolution: `note_registration` cannot be restricted across named modules;
  it is observational only and saturating, and is covered by characterization tests.
- `acceptance/source_capture.*` is intentionally unedited. `open_bound` already performs
  original-root discovery with `same_selection` and actual-leaf verification in the native
  layer, covered by the existing D2-B2/C01 tests. The `same_selection` mutation probe
  therefore targets that native/`source_capture` layer in the scratch copy.
- Known limitation (reported by P2): some defensive branches are unreachable through the
  public API and are exercised only where a same-module observer allows.
- Dependency audit: no CMake edit was required (see the evidence report).
