## C2 verification obligations

The following are acceptance obligations, not executed results:

| Boundary | Required observation |
| --- | --- |
| Write transaction fails at successive writes | All old rows/projection remain; no partial new state |
| SQLite page allocation reaches its configured maximum | Actual `SQLITE_FULL`, rollback and usable connection/reopen; no pruning |
| Injected SQLite write/sync error | Typed failure, no false commit success; reopen validates complete old/new state |
| Child killed before commit, during commit, after commit | Real subprocess status and restart evidence; complete old/new state only |
| Competing processes | Bounded busy refusal, writer release and subsequent successful transaction |
| Backup/publication fault before publication | No target; owned staging cleanup or explicit cleanup failure |
| Parent sync/cleanup failure after publication | Explicit uncertainty; published complete target retained |
| Sidecar appears before publication | Refusal without overwriting it or publishing an unusable target |
| Full milestone | Nonzero complete debug/release registry, zero skips, renderer acceptance and no-work builds |

Use test-only interposition or a test VFS where needed, with no product-global
fault switches. A configured SQLite page limit establishes SQLite-full behavior,
not physical host-volume exhaustion. Symbolic transaction fixtures establish
storage atomicity, not acceptance/event policy. Record macOS execution and any
unexecuted Linux coverage explicitly.
