### Authority analysis against criterion 9 (X06-C acceptance table row 9, and criterion 1 of this round)

What changed: `native_candidate` lets a caller supply the source, registry and stdlib trees, workspace id, interpretation and
versions bytes, a `verify()` callback that runs inside the write transaction, and `selects_profile()`, which switches off the
embedded "Unsupported profile acceptance" refusal. Before C01 all of it was exported from `planar.engine.ledger.acceptance` to every
importer, including `src/cmd/planar/invocation.cpp`. Now:

- Language-level hiding: a plain importer of `planar.engine.ledger.acceptance` cannot name the seam (private import, nothing
  re-exported), and the exported surface is the two embedded overloads plus `acceptance_result`. The profile module exports only
  `complete_acceptance(path, intent, const prepared_profile&, identity, receipt&)` and re-exports `ledger.acceptance`, not the seam
  (mutant C01 re-exporting it from the profile module is killed).
- Not language-level: C++ module names are not access controlled. Any target that links `planar_ledger_acceptance_seam` could
  `import planar.engine.ledger.acceptance_seam;`. The C01 text here claimed the link graph restricts reachability; that was false and is
  withdrawn (C01 review R2): `planar_rewrite_module` links DEPENDS PUBLIC (`cmake/rewrite.cmake:23`), so 67 `src/cmd/planar` targets carry
  the seam in their link closure and probe C22 imported it by name. In C01 only a test enforced it: the R1 test scans all `src/**/*.cpp(m)` and fails if a file other than the seam, the two adapters and their tests mentions
  `acceptance_seam`, `native_candidate`, `candidate_values` or `complete_native_candidate` (killed: C22). It is a source-text check,
  not a name-lookup probe or negative-compile test; an indirect re-export through some other module that avoids all four words is
  not detected. C01 added no passkey, so its compile-time proof was met only in this textual form (criterion 1 below). The operator
  then chose the passkey (C02 record); the structural enforcement is the private `seam_key` constructor, with the R1 scan as second check. (Superseded: the passkey was forgeable per C02-R1 and is withdrawn; C03 replaced it with a non-exported partition.)
- What the prevention does not cover: the two in-tree adapters remain trusted code. The seam itself does not check that the
  values it receives come from a real prepared profile; the embedded adapter wraps `prepared_acceptance`, the profile adapter wraps
  `prepared_profile`, and nothing in the seam rechecks that. The only dynamic defence is storage verification (the verify-before-commit
  re-derivation of the stored trees against the recorded interpretation, `storage.cpp` consistency check), which refuses an
  inconsistent fabricated candidate ("Accepted history is inconsistent") but would accept a self-consistent one. The opaque
  `prepared_profile` type and the I9 guard (no overload takes `profile_acceptance_data`) remain the authority for profile completion;
  the architecture document's private tagged adapter is realised as the module split rather than a tag type.
- Also unchanged: no new construction path for `prepared_profile`, `profile_acceptance_data` or a receipt; no change to
  `src/engine/runtime/*` or `src/cmd/*`.
