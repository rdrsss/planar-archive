## API and precedence pinned before implementation

interpretation(encoded,versions_encoded) returns non-authoritative family hint;
verify_recorded_interpretation(encoded,versions_encoded,raw_files,workspace)
returns ordinary owned result with family/status(decoded or unsupported), optional
canonical payload only for decoded, and recomputed tree digest. Pure errors:
malformed, unsupported_manifest, resource_limit, invalid_tree,
invalid_correspondence. Unsupported result contains no semantic payload.

Both-size preflight then canonical envelope then separateV decode; effective
marker presence means extensions or provenance/registration in embedded/separate
versions, with safe record-kind checks. Numericversion alone never selects family.
Final repeats classification, releases initial values before provenance copies.
Provenance verification precedes lower decoder syntax/unsupported; strict known
effective manifest envelope keys/types/module/catalog containers precede future
version/scheme unsupported classification. Unknown embedded manifest uses existing
verifier category. Known manifests use unchanged approved pure verifiers.
Then oldv1 or mandatoryrawtree A1v2 decoder. Lower unsupported guarantees fixed
shape/separateV checks; bounded redecode extracts only workspace/digest for
integrity. Mismatch refuses invalid_correspondence even for unsupported; valid
unknown returns unsupported without semantic payload. Supported also matches
workspace/digest. Canonical classification failure precedes provenance; lower
malformed precedes workspace/digest. Preserve all typed resources, including
canonical/preflight/lower verification and bad_alloc. Repeated bounded decoding
and A1 rawtree reverification are explicit, no private aggregate bypass or new
sameVM/accounting guarantee. Tests pin these choices before downstream A3 wiring.

Manifest-preflight refinement: after classification, fixed-profile digest_tree
validates raw topology/bounds before manifest preflight. Preflight checks exact
known envelope keys/kinds, bounded module entry/path/normalized-mode syntax and
catalog container keys/kinds only. It does not duplicate contextual catalog/
owner/embedded-sequence verification before refusing an unknown manifest. Unknown
manifest never returns exportable or semantic success; known manifest immediately
uses full approved verify_effective_stdlib. Malformed-before-unsupported here
