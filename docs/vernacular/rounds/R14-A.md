## Search handoff and bounded sequence

Fresh `/root/r14a_search` confirmed extraction into two units:

- A1: shared ledger value/error DTOs and pure tree algorithms, with existing
  owner APIs retained as thin adapters.
- A2: pure provenance and recorded-interpretation codecs, with existing embedded
  source and live Lua preparation retained above them.

The first search cautioned against moving storage policy downward. A1 moves only
inert data vocabulary (`format_error_code`, `format_error`, record reference and
stored record), never open/transaction/SQL behavior. This preserves exact typed
failures without side channels or translating them twice through callback errors.
The format module re-exports its current public names as explicit aliases of
leaf declarations; the tree core consumes those leaf types directly. The
mechanical fault/collision generators replace only the exact namespace declaration,
so fully qualified leaf aliases can remain intact without new source mutations.

The second unit will use the pure tree core and canonical/value leaves. Future
format history verification will import these leaves, not live owner/embedded/
Lua wrappers. No history acceptance is enabled in either extraction unit.
