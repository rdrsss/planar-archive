## Dispatch (2026-10-30, coordinator)

### Objective

Make the process that loses a compare-and-swap race during `planar load` report `revision_conflict` (exit 3) and never the
internal `Invalid external profile protocol` (exit 4). Today `x07.two_process_cas_one_winner` flakes under CPU load: the
loser admits the ledger file as a captured input (`admit_ledger` and `open_known_load` in `src/engine/runtime/runtime.cpp`,
about lines 5162 and 5294, role `admission_file_role::ledger`). When the winner commits after the loser's admission and before
the loser's `acceptance_capture::verify` (`src/engine/capture/native.cpp` near line 947), verify fails with `capture_changed` /
`Captured inputs changed during verification`. That message is not in the closed external-profile message table, so
`registration_failed` in `src/cmd/planar/invocation.cpp` (`execute_profile_load`) redacts it to `internal` exit 4. The race
predates X08 and was recorded in the X08 and X08-C01 records. Operator decision 2026-10-29: fix it as X07-C02 before RA01.
The failure was seen once, in X08-C01 gate run 1 (`tests/native/v5-02-x08-c01-evidence/raw/05-ctest-release.log`, local, with no
diagnostic captured) and reproduced by the X08 owner in release with 12 busy loops.

### Governing clauses (quoted, binding)

- Ledger contract, load step 3: "Look up the request again: another writer may have committed during capture; exact body
  replay/conflict still precedes CAS."
- Ledger contract, load step 4: "For an unknown request require expected head equal current active head ... A mismatch refuses
  `revision_conflict`, even if content equals the current head. No new request row survives refusal."
- Ledger contract, load step 5: the retained-receipt recheck comes after CAS, and "closure membership is determined by the captured
  declarations and references: unrelated workspace additions/removals/edits do not block acceptance"; a detected closure change
  refuses `capture_changed`.
- External-profile contract (X-CAP): "No unrelated sibling membership check in the trusted directory: only listed closure and
  necessary ancestor identities matter." Reverify "with all acceptance receipts immediately before load commit under lock".
- External-profile contract message table is closed: the receipt row is `capture_changed` / `Captured external profile changed`,
  and "existing propagated native errors keep their exact messages".

Reading: the ledger file is the store being compared, not a declaration or profile input. Its being changed by a concurrent
committed writer is exactly the stale-head case, and the contract orders the CAS (step 4) before the receipt recheck (step 5).
A lost CAS therefore yields `revision_conflict`. Two fixes fit that reading: (a) stop treating the ledger file as a native
capture receipt that fails verify, relying on the locked identity/format recheck and CAS for ledger integrity; (b) keep the
receipt but, on a ledger-only change, run the locked relookup and CAS and report `revision_conflict` (or the exact replay if the
request id was committed meanwhile). Search chooses between them and records the choice in `plan/DECISIONS.md` as "new within
contract" with the clause cited. If search finds the contract silent or two readings plausible for a reachable case (for
example ledger replaced by a different ledger, or ledger change together with a real input change), the run stops with an
operator question and options instead of choosing. Required to stay true under either fix: a real change to a profile, module,
registry, declaration or ancestor input still refuses `capture_changed` (the existing receipt-race cases in
`x07.receipt_races_refuse_before_authorization` and `x07.final_race_rolls_back_before_commit` pass unchanged), a replaced or
foreign ledger identity still refuses by the existing identity recheck, and no diagnostic byte changes.
