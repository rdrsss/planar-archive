## Findings

1. P2 — final text normalization does not implement the approved contract. stdlib/planar/schema.lua:126 and :129 produce kind:file/path/bytes and kind:md/bytes, respectively. render-contract.md:247–251 requires kind:text/bytes for both, plus file:{root:workspace,path} for captured file text. README:168–170 describes the differing representation as normalization, rather than a provisional stage; B2 currently inherits it. Production normalize_bundle on the unchanged quota fixture confirms goal.kind=md, expected.kind=file, and expected.file absent. Use the final contract representation now; keep route-only unresolved file descriptors explicitly provisional. Preserve exact bytes and declaration-relative path. Add native production assertions for inline/file text, wrapped notes and provenance.

2. P2 — ID-keyed record collections retain declaration order. schema.lua:94–107 sorts only schema.set, despite all ID-record lists carrying schema.key. README:181–184 explicitly preserves work/milestones/roles/registry order, contradicting render-contract.md:247–249. Unchanged fixture returns spec.work IDs library,command; reversing declaration work changes normalized order to command,library. This allows order-only edits to affect later semantic inputs unless B2 invents another normalization. Sort ID-keyed collections here: workspace.jobs and corresponding bundle.jobs by job ID; spec work, milestones, constraints, prescriptions, contracts, facets, dependencies, questions; job.roles; registry toolchains/checks. Keep original indexes for source diagnostics. Preserve acceptance-criterion order and outer pipeline-stage order, as required explicitly; command/argv string lists remain ordered too. Do not sort acceptance merely because its records also contain IDs. Set contents remain sorted. Add permutation-stability and true-ordered-list regression checks; update README and contradictory assertions.

3. P2 — JSON depth limit admits 129 nested empty containers. json.lua:115–127 checks depth>128 with the root at depth0; the empty-container return bypasses any deeper parse. README:134–136 promises at most 128 nested container levels. Production parse_json accepts '[' repeated 129 + ']' repeated 129, but refuses the same 129 containers around scalar 0. Check container entry depth consistently, accepting exactly 128 both empty/nonempty containers and refusing 129; include objects and mixed nesting in the boundary test. This remains bounded, but does not enforce its declared bound.

4. P2 — final bundle validation does not validate joined declaration paths before using them as diagnostic provenance. schema.lua:248–255 concatenates workspace directory with spec/job paths without the path_valid checks used by route_workspace at :204–208 and text resolution at :120–121. With a valid 916-byte workspace file and valid 128-byte listed job filename, normalize_bundle emits reference/Listed job not captured with a 1031-byte file. That violates declarations.md:75 and README:118–119's validated portable logical-path guarantee. Validate resolved spec/job paths before lookup/matching/issuing logical-file diagnostics; attribute path_denied to the valid declaring workspace path and relevant workspace field. Add post-join boundary tests for both spec/jobs and route/final consistency. Normalizing fabricated caller records need not authenticate capture, but must still validate paths and keep diagnostic guarantees.
