## Reviewed contracts and conclusions

Read `CLAUDE.md`, R11's assigned brief, the complete implementation plan and
roadmap, the complete ledger candidate, v4 lines 430–468 and acceptance
A20/A23/A25–A29, declaration/render v1, current capture interfaces, trusted
normalization/semantic outputs, canonical implementation, and stdlib embedding.
The approved breaking rewrite supersedes legacy coexistence/migration duties;
it does not remove new-format evolution or recovery obligations.

- Source and provenance are reconstructable immutable byte/mode trees, separate
  from complete normalized/semantic values. The interpretation envelope matches
  the actual `normalize_bundle` result fields and relevant `validate_bundle`
  outputs (`src/stdlib/planar/schema.lua:220–298`,
  `src/stdlib/planar/semantic.lua:57–72,353`). Old interpretation is decoded under
  recorded codecs, not regenerated by today's Lua. Exact registry/stdlib bytes
  are retained separately (ledger contract lines 59–97, 259–267).
- Binary records are distinct from JSON/canonical_v1. Directory digest preimages
  omit local IDs while preserving portable names, kinds, metadata and child
  digests. Equality includes the exact child IDs/encoded bytes. Nonunique digest
  indexes, refusal of unequal equal-digest records and complete exact no-op
  comparison meet v4's collision requirement. Bottom-up records and
  `parent_id>child_id` avoid cyclic tree construction; revisions point only to
  earlier chronology (lines 99–159, 183–210, 254–258, 279–297).
- Existing signed-32 canonical/Lua semantics remain intact. SQLite signed-64
  IDs and sequence values cross public/Lua boundaries as bounded decimal strings.
  Raw BLOB payloads do not become JSON text. Bounds and conservative portable
  path/mode rules are explicit (lines 101–159).
- Initialization/event/current-state insertion has no circular FK dependency.
  Accepted and no-op loads can insert revision/event/request/projection rows in
  the specified transaction. The DDL intentionally leaves semantic cross-row,
  typed payload and codec checks to the native invariant checker; the contract
  explicitly enumerates that obligation rather than claiming SQL alone proves
  it (lines 175–277, 299–312).
- Original-result replay occurs before recapture and current-head CAS, including
  the second lookup after acquiring the write transaction. Exact request bodies
  include actor, expected head and normalized explicit paths. Changed/gone draft
  files or a later head cannot rewrite a committed intent, and changed parameters
  conflict. Unknown requests use CAS; no-op preserves revision chronology while
  revert allocates a new revision with the current parent. Invalid capture or
  transaction refusal preserves accepted state (lines 314–369).
- The acceptance-only retained receipt verifier is explicitly new work, so the
  design does not pretend sealed `capture_session.finish()` can perform later
  I/O. Cooperative limitations remain explicit. Current render stays sealed,
  database-free and unchanged (lines 341–350, 381, 406–410;
  `src/engine/capture/capture.cppm:57–65`).
- New-format identity/schema/integrity verification precedes writes, with an
  explicit recognized-v1 hot-journal recovery exception. Unsupported/foreign
  files refuse without mutation. Explicit initialization/export use safe new
  targets, owned staging, no-replace publication and uncertainty/cleanup rules.
  Disk-full/crash, backup/restore, retention and future offline new-format
  migration policy remain concrete obligations (lines 425–486).
- The staged roadmap is bounded: R12 storage/dependency/transaction primitives,
  R13 codec/trees/provenance, R14 acceptance/history/export. Handler ownership,
  CLI11 parsing, prepared SQLite, Glaze output and product-under-`src/` rules
  carry forward. Roles, runs, checks, scheduling and claims are deferred with
  explicit remaining acceptance obligations, including atomic reconciliation
  before enabling execution (lines 19–25, 32–57, 488–522; roadmap R12–R19).

V4 A20's active-history survival, A23's storage/format failure safety, and
A25–A29's chronology, atomicity, collision, exact-tree and reconstructable-history
requirements are preserved for the foundation. Draft status, role materiality,
dispatched context and execution-state portions are explicitly deferred, rather
than represented as implemented by this foundation. No unresolved product choice
was found that prevents the bounded implementation sequence.
