## Finding and contract

Native read_file traverses each file's intermediate directories with no-follow
opens, but only tree enumeration records their identities. Closure-only loads must
not enumerate the whole workspace. A changed ancestor can therefore escape the
current receipt check if the original file inode is linked into a replacement
directory at the same logical path. Fix this necessary-directory identity gap,
without acquiring unrelated membership or bytes and without changing render output.

Record identities of intermediate directories actually traversed for successful
retained file reads, keyed by logical root/portable ancestor path. Root identity
and standalone registry parent are already root receipts. Verify selected ancestor
paths through retained root descriptor/no-follow traversal against original
identities during initial sealing and repeated acceptance verification. Detect
inconsistent ancestor identity across discovery reads too. Verify must not rewrite
receipts, mutate alias maps or publish new values. Do not compare directory mtime/
ctime/membership: unrelated sibling edits, additions, removals, rename, inaccessible
files, links and oversized unrelated files must not affect closure-only acceptance.
Whole-tree capture retains its independent full membership/topology checks.

Use a separate internal receipt map or equivalent, not public tree topology; adding
closure receipts must not populate directories() with entries that were never tree
captured. Retain existing root/path confinement, hardlink alias refusal, normalized
0644/0755 semantics and immutable snapshot lifetime. Private receipts need no
public source or serialized format change. Native capture is shared by render;
explicitly verify unchanged render output and old full-tree cases. The new ancestor
identity refusal is intentional for selected file reads in both sealing paths.
Host ancestors above the registered root retain existing no-follow root reopening
contract; this unit tracks workspace-relative ancestors, not a new global host-tree
inventory. No recursive unrelated enumeration.

Bound receipts under existing finite path/file/tree limits; avoid one held fd per
ancestor. Repeated reads must not multiply receipts; handle allocation failures/
moved-from sessions consistently with existing native lifetime/error rules.
Map verification-detected replacement/removal/link to capture_changed. Initial
invalid discovery paths keep existing path_denied/io classifications. Failed reads
must not create misleading public snapshot/topology claims; retain existing failed
session behavior. No optional verifier bypass or production callback addition.
