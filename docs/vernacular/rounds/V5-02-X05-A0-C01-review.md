## A0-R1 is closed

The correction in [generate.py](../../../tests/native/v5-02-x05-a0-support/generate.py) reserves `audit_stack_slots` with `lua_checkstack` at the beginning of the actual protected `seal_environment` C frame, before root pushes or destructor-bearing audit work. Pinned `lua_checkstack` updates the current `ci->top` (`vendor/lua/0b10/src/lapi.c`:110–125); `precallC` gives a new frame only `LUA_MINSTACK` slots (`ldo.c`:642–649). The fix therefore repairs the frame transition identified by R1, rather than only enlarging backing storage.

[audit.cpp](../../../tests/native/v5-02-x05-a0-support/audit.cpp) rejects insufficient current-frame capacity before `make_unique`, PMR construction or any Lua push. After checking nonnegative bounded relative top `t`, the test `ci->top-top >= 2048-t` means the frame permits relative top 2048. The graph entry ceiling remains 2040. Table traversal can add a key and value, reaching at most 2042 before the next graph-entry ceiling check; root and catalog slots are already included in relative top. Every potentially growing graph operation and the initial catalog read additionally checks actual frame headroom. The audit never calls `lua_checkstack`; raw reads, stack copies and upvalue reads do not allocate through Lua. Native allocation/work refusals restore the original top and release native storage through ordinary C++ unwinding.

A failed generated-frame reservation sets the existing `stack_exhausted` flag and returns zero with only trivial locals alive. The unchanged protected caller checks exhaustion immediately after `lua_pcall` and produces its existing stack resource diagnostic. The audit's RAII starts only after successful reservation; its expected result leaves scope before any later `luaL_error`. No Lua allocation/longjmp path crosses live audit ownership.

The independent [probe runner](../../../tests/native/v5-02-x05-a0-c01-review-evidence/run-probes.py) compiled review-owned copies using the frozen candidate's compile/link metadata. It reproduced the original reviewer's exact graph-entry diagnostic against the original copied runtime and audit: **exceeded_by=2, physical_headroom=3049**, shipped bundle refused. The correction was then linked to a copied audit with independent pre-operation checks at every `lua_pushvalue`, `lua_pushnil`, `lua_next`, `lua_getupvalue` and initial catalog `lua_rawgeti`, including the corrected loop syntax. The exact shipped five-handler bundle accepted with no invariant failure. The original independent C-frame probe, changed only to reserve within that frame and use 100 tables, also accepted with entry headroom **2048**, protected status zero and no invariant failure.

The independent runner also verified every reversible substitution in the controlled failure fixture, compiled it again and ran actual `command_vm::create`. That evidence-only variant lowers the earlier caller reserve to 20, uses supported full GC before installing a growth-refusing allocator, and leaves the new active-frame request at 2048.
