## Implemented scope and controls

The two existing descriptor cases capture the test process's pre-existing
nonstandard descriptors before creating the cwd or original held-file subjects.
The fixture enumerates `/dev/fd`, excludes its own directory observer, closes
that observer, then records original flags and file identities and temporarily
sets `FD_CLOEXEC`. Restoration leaves descriptors open, restores their original
flags, and rejects changed file identities instead of altering later subjects
that reused a number. The single-threaded fixtures retain each pre-existing
descriptor until restoration.

A dynamically duplicated inheritable marker is required to be greater than 3
and within the unchanged probe's 3–63 range. Both cases check its original flags,
normalization during isolation, validity and exact flags after restoration.
The negative case additionally forces setup failure after the first flag change
and verifies immediate rollback, then verifies destructor restoration during
exception unwinding. These controls run inside existing cases.

All original assertions remain, including exact empty negative output and exact
`9\n` positive output. The macOS intentionally inheritable held subject is still
created after isolation; its flag is explicitly checked immediately before
spawn, preserving the `CLOEXEC_DEFAULT` sensitivity requirement. The fixture
does not capture or normalize resources subsequently created by `run`.
