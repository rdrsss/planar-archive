## Search and initial architecture direction

tree/provenance/interpretation implementations, capture's missing post-seal
receipt verifier, CLI11 handler wiring and partial file-publication primitives.

transitions, backup and recovery. Merely allowing populated history in the low

those existing entry points. Do not enable that intermediate product state.

record/error DTOs and storage-independent tree traversal/construction, provenance

modules. Keep convenience owner APIs and live embedded/Lua preparation above
those leaves, re-exporting existing public names where practical. Typed record
reader/intern callables are explicit local algorithm inputs if needed, never
global callbacks, SQL strings or escaping SQLite handles. The same pure checks
must serve existing public wrappers and later internal format verification.

reviewable units before coding. Current schema and all record-only/history refusal
remain unchanged during it. Only after the pure boundaries are approved should
a separately searched slice add streaming complete v1 chronology, request/event/
projection and referenced-content validation across all opener/backup/recovery
paths. History has no total cap; verification streams rows in one snapshot and
bounds each complete referenced tree/value rather than materializing all history.
Unsupported historical interpretation versions must not prevent supported raw
source access, while malformed supported structure remains refused.

The subsequent sequence remains typed atomic append/request/head APIs, retained
acceptance capture receipts, pure preparation and replay/CAS/no-op/revert service,
thin init/load/history handlers, exact export, then full integrated gates. Narrow
subrounds receive their own fresh search/coder/reviewer. No acceptance writer is
