### host_path pre-check design

`src/engine/capture/host_path.cpp` gains a file-local helper `reject_file_parent_traversal` (anonymous namespace, not exported from
`host_path.cppm`; no public symbol or field). `host_directory` calls it first, before `std::filesystem::canonical(absolute)`.
It walks `absolute.relative_path()` lexically, accumulating a prefix from the root path and skipping empty and `.` components exactly
as the walker below it does. When a component is `..` and `std::filesystem::status(prefix, ec)` (not `symlink_status`, so a link
to a file is covered) reports no error code, an existing entry that is not a directory, it throws io "Cannot resolve explicit
root directory". Any error code (missing parent, loop, ENOTDIR from an earlier segment such as `file/x/..`, permission) does
nothing, so those spellings keep io "Cannot resolve explicit input path". It is not an `#ifdef`; the file gains no `__APPLE__` or
`__linux__` token. `resolve_explicit_file` does not call it and is unchanged. It is not a security change: no accepted input is
widened and the final-root-alias and symlink-walking refusals are untouched.

### Both macOS mapping changes (decision 5, operator)
