# V5-02-X06-B1: native completion dependency extraction

## Dispatch (2026-10-24)

### Objective

Deliver the first X06 code round from the "Bounded delivery sequence" in
[the profile preparation architecture](../profile-preparation-architecture.md).
The round restructures native storage and acceptance code so that a later profile
transaction can share one common algorithm without creating a target cycle. It
adds no profile writer, no profile overload and no behavior change. The embedded
APIs, every native boundary, atomicity and recovery case, and the A3 readers must
behave exactly as before; only module ownership and imports change.

### Dependencies

X06-A4 plus C01 is independently approved
([review](V5-02-X06-A4-C01-review.md)); X06A4-R1 is closed. The round builds on the
approved X05-C5 and X06-A3 code. Nothing earlier than this round is pending.

### Owned scope

New files:

- `src/engine/ledger/storage_types.cppm`: inert relocated definitions of
  `ledger_format`, `ledger_metadata`, `ledger_access`, `history_head`,
  `revision_row`, `event_row`, `request_row` and `event_page`, with namespaces and
  layouts unchanged. It imports `ledger.types` and `ledger.history_codec`.
- `src/engine/ledger/storage.cppm` and `storage.cpp`: reusable native storage
  internals moved from `format.cpp` (location and descriptor identity,
  `format_state`, selected-schema verification, `same_metadata`, decoding and
  interning, locked writer mechanics) and the opaque thread-confined
  `write_transaction` with `begin_write(path)`, as specified in the architecture.
  No raw SQLite handle, callback or caller SQL is exported.
- `src/engine/ledger/acceptance.cppm` and `acceptance.cpp`: `acceptance_result`,
  `complete_acceptance`, native helpers and the completion algorithm moved out of
  `format.cpp`. It imports prepared, intent, storage and completion, and does not
  import runtime. The existing explicit fresh-profile refusal stays in the common
  algorithm. No compatibility re-export from `ledger.format`.
- `src/engine/acceptance/intent.cppm` and `intent.cpp`: `request_data` and
  `request_intent` moved unchanged from prepared; prepared re-exports intent.

Edited files: `src/engine/ledger/format.cppm` and `format.cpp` (remove acceptance
declarations, prepared import, friend declarations and `complete_acceptance_impl`;
re-export storage_types; facades over storage), `src/engine/acceptance/prepared.cppm`
and `prepared.cpp`, `src/engine/CMakeLists.txt` and `src/cmd/planar/CMakeLists.txt`
(targets, dependencies, generated and fault/digest test variants), and the module
imports of existing consumers and tests found by search (including
`src/cmd/planar/invocation.cpp` and the ledger tests such as `acceptance.t.cpp`,
`publication_fault.t.cpp`, `snapshot.t.cpp` and `history_verification.t.cpp`).
Test files may change only their imports and target wiring, plus any new focused
tests search proves are needed. Search confirms the exact consumer and generated
variant list and splits packages with exclusive ownership. Files not named here
belong to others and must not be touched or reverted. The only other files this
round may write are its own evidence folder, this record and, at the end, the
roadmap status.

### Acceptance criteria

1. Exported embedded APIs keep their signatures and semantics after the changed
   imports. Every existing native boundary, atomic, recovery, commit-uncertain,
   publication-fault, snapshot, history-verification and A3 reader case still
   passes with unchanged expectations. Registered inventory stays at least 918 with
   all prior names preserved.
2. `ledger.storage` does not import runtime, prepared or `ledger.acceptance`, and
   `ledger.format` does not import `ledger.acceptance`. A dependency audit of the
   CMake targets and module imports proves no target cycle, including generated
   and fault/digest variants. All generated variants build.
3. No raw handle or callback escapes `write_transaction`. Failed storage operations
   poison and roll back. Entry and precommit metadata checks are not collapsed.
4. No profile writer, no `complete_profile_acceptance`, no runtime edge from
   acceptance, and no public CLI or format change. Fresh profile acceptance still
   refuses and public init still creates format1.
5. The search re-anchors the "around" line citations in the architecture's runtime
   and native source anchors (advisory X06A4C01-N2) and reports the current lines.
   Advisory N1 applies to the later source-capture round, not this one.
