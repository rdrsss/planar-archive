## Search handoff and concrete decisions

Fresh `/root/r13c1_search` confirmed the narrow factoring boundary:
`tree.cpp` input validation/trie (currently in `build_tree`) can be shared with
`digest_tree(files, profile)`. Both paths use the original record codec; hashing
uses positive placeholder child IDs only because those IDs are omitted from the
portable preimage. Storage still uses exact real local IDs, collision checks
and the existing abort guard. Test pure/committed digest equality across local-ID
changes and preserve every B2 refusal/exception guarantee.

Extend generated embedding with ordered original portable paths/byte views and
an exact separator view, preserving `source()` bytes. Paths are relative to
`src/stdlib`, never host paths. Add a small native provenance preparation module
owning sorted file entries plus the pure portable root digest. Registry preparation
accepts captured bytes/mode and emits exactly `input.json`. Stdlib preparation
accepts ordered originals, separator and exact assembled chunk, or obtains these
from the generated embedded module; it verifies assembly before returning.

The canonical manifest has exactly `version:1`, `scheme:"ordered_concat_v1"`,
`files:<ordered list of original portable path strings>`, and
`separator:<exact bytes>`. Each original contributes its exact bytes followed by
separator, including the last. Current generated separator is one LF. This scheme
can represent other separators without inventing a new implicit concatenation
rule; changing separator changes identity. Original and synthetic stdlib files
have normalized mode 0644. Reject reserved namespace collisions (including case
aliases), duplicate/unsafe paths, missing/extra original files, inconsistent
chunk bytes, malformed/unsupported manifests and wrong modes. Decode/verify a
reconstructed provenance set through canonical_decode and fixed native envelope
validation without running Lua. No hand JSON/canonical serialization.

Apply provenance limits to the entire original-plus-synthetic set, including
manifest/chunk bytes and the two synthetic files. Bound counts and byte sums
before copying or allocating assembly scratch; reject overflow. Reuse B2 path
and topology validation, rather than maintaining another path grammar. Keep
generic original views separate from owned prepared output so callers cannot
accidentally store an unverified manifest as a successful preparation.

Confirmed ownership is the provisional list above plus new
`src/engine/history/provenance.cppm/.cpp/.t.cpp`. Preserve existing Lua product
files, runtime implementation, format/schema/SQLite and record codec. Include
reproducible checks that generated originals equal authored source bytes and
`source()` equals the pre-change assembly, plus CLI acceptance on the fresh
binary. Freeze exact candidate/evidence for fresh independent review.
