1. The format3 schema ([EX-1](../execution-contract.md#ex-1-format3)) as one complete schema written once, including the
   tables reserved for R16 to R18, the update and delete triggers of the immutable tables, and the exact-stored-SQL
   verification by the opener. Module `ledger/execution_schema`.
2. `request_v3` framing and replay ([EX-2](../execution-contract.md#ex-2-request-framing-and-replay)), the run token
   text and secret rule (R15-9), and the execution codecs for payload v2, packet, manifest, transitions and the
   `driver_provenance_v1` value record (EX-8 bounds). Modules `history/request_v3` and `history/execution_codec`.
3. The format3 snapshot read and cross-row verification (EX-1 and EX-4 invariants, role lineage and generations of
   EX-5 as stored facts, event and transition consistency), refusing format1 and format2 for execution operations with
   `unsupported_ledger_version` before any capture or Lua ([Common rules](../execution-contract.md#common-rules), item 1).
4. The EX-3 execution commit protocol: write transaction, preconditions on `fact_version`, `current_state` and
   `role_state`, delta write of the mutable projections (never a complete vector), identifier allocation `MAX+1`, event
   and transition rows, run token generation, fencing of old runs, and the EX-7 refusal codes and EX-8 bounds that the
   storage layer owns. Module `ledger/execution`. The commit is exercised through a native test-only entry that supplies
   the reconcile output as data, because Lua reconcile is R15-C.
5. Format3 initialization as an internal native function used by tests only. Public `init` keeps creating format2.

### Out of scope (must not be done)

- No CLI verb, no handler, no root help or catalog change, no admission row, no `command_options` change (R15-D).
- No `reconcile.lua`, no `dispatch.lua`, no dispatch projection, no `work_exec_v1` computation, no change to
  `runtime.cpp`, `commands.lua`, `schema.lua` or `semantic.lua` (R15-C). If a package nevertheless edits any of them, the
  boundary pin rule below applies.
- No format3 load or `activate` reconciliation in `ledger/acceptance*` and no init cutover (R15-C). The X06-C seam and
  its threat model (XD1) stay untouched.
- No check, verdict, refresh, checkpoint, release or recover behaviour (R16 to R18); reserved tables get schema only.
- No change to a closed diagnostic message byte; execution messages only as the contract's Messages section lists
  them. No public field or method added to a product type only for observability.

### Acceptance criteria

Taken from the contract's acceptance checklist, restricted to what exists without Lua and without a CLI:

- Schema: the exact format3 SQL verifies; every immutable table refuses UPDATE and DELETE; a one-byte difference in the
  stored SQL, a missing trigger or a wrong `user_version`/format marker makes the opener refuse.
- `request_v3`: bytes and replay rules of EX-2, same ID with changed content conflicts, same ID with same content
  returns the saved bytes (including the token), after later events.
- Commit: the lost-update guard (two commits of different roles both succeed and both roles end as written; the
  permissive "write the complete vector" mutant is killed), precondition mismatch refuses `state_conflict` with no
  effect, injected fault before COMMIT leaves no event, transition, run or fencing (A26 and A23 storage halves), a
  concurrent writer between snapshot and commit is detected (A09 storage half, pause variant at the native level).
- Fencing: after a takeover-shaped commit the old token refuses `fenced` with no effect (A10 storage half); a regrouped
  role name gets a new generation and no inherited token (A22 and A33 stored-fact half, rows M9 to M16).
- Cross-row verification rejects hand-corrupted ledgers row by row (each EX-1 and EX-4 invariant has a corrupting test).
- Format1 and format2 ledgers refuse execution operations with `unsupported_ledger_version`, and existing load, history
  and export behaviour on them is byte-unchanged.
- EX-8 bounds are enforced at write and at read (at-limit accepted, limit plus one refused).
- Pins carried from R15-A2 advisories A1 and A3 (D149 `state_conflict` reuse at two snapshot-time sites; the missing
  `dispatch_context_v1` field list): D149 is pinned by a test of the storage-level refusal site if the commit layer owns
