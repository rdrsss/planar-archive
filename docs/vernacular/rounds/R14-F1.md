No legacy Planar tools or operator state, commits, installs, publication or merge.

API takes explicit ledger path, positive signed64 revision ID and explicit new
 target directory path. Returns ledger identity, revision and source record ID
or typed native export failure. Native IDs remain integers until future CLI.
Open ledger once read-only; look up revision (typed revision_not_found on absence),
read source record for exact root reference then read_tree(source profile) through
that same owner. Fully reconstruct and validate all files before any target-side
creation. Owned vector avoids DB reads while materializing. No interpretation
version requirement or Lua/current policy. Source limits remain64MiB/4096files/
8192dirs/depth64/path1024; no new unlimited traversal. Nothing except source files
and necessary ancestors goes into target; empty source root is supported by tree
API where valid, nonroot empty dirs remain refused.

Resolve explicit target original components before lexical normalization, matching
native ledger semantics. Missing/.. does not erase a failed traversal. Reject
symlinked parent components, invalid final basename, trailing separator/dot target,
and any existing final entry including emptydir/file/link/danglinglink. Hold real
parent descriptor. Absolute/relative paths both work; no implicit default paths.
Preflight target absence is only an early check; final no-replace publication must
atomically refuse a target arriving later.

Create exclusive unpredictable sibling stage `.planar-export-<random-hex>` mode0700;
retain stage/parent identities and descriptors. Create only validated relative
source paths with O_EXCL/O_NOFOLLOW and descriptor-relative opens. File staging
mode0600, exact full writes (handle EINTR/short writes, reject zero progress), final
mode0644/0755 independent of umask, fsync after chmod. Dirs initially0700, then0755,
sync bottom-up including stage root. Close errors must not produce success if
required writes might have failed. Avoid retaining thousands of descriptors:
resource usage must support profile bounds under normal descriptor limits; retain
identity receipts and bounded-depth traversal rather than one fd per file/dir.

Same-parent publication uses renameatx_np(RENAME_EXCL) on macOS or
renameat2(RENAME_NOREPLACE) on Linux. Verify exact local SDK declarations and guards;
refuse unsupported kernel/filesystem/platform capability without unsafe fallback.
Never use plain overwrite rename or check-then-rename. After successful rename,
mark published before any subsequent potentially failing operation and fsync parent.
No target deletion after publication, even after sync/close/allocation failure.

Prepublication failure removes only invocation-created entries whose current
identities and descriptor ancestry still match receipts, children before parents.
Do not recursively remove unrecognized/replaced entries; report incomplete instead.
Cleanup must run on every error and exception (RAII), without throwing in unwinding.
No automatic adoption/deletion of prior crash stages. Cooperative local ownership
assumption remains; don't claim safety against a hostile concurrent directory owner
or power-loss immunity. Bounded memory and fd lifecycle are part of review.

## Error vocabulary and later CLI mapping

Native error distinguishes underlying ledger errors, revision_not_found,
invalid_argument/path_denied, target_exists, ordinary io, publication_uncertain
and cleanup_incomplete. Tree malformed/bound failure after verified open maps to
ledger_corrupt; preserve actual storage category from tree_error when available.
Never return captured bytes/private paths in messages. A cleanup-incomplete error
may carry ONLY the invocation-generated stage basename (strict generated grammar),
not target basename/parent/fullpath. Identity mismatch means location may have
changed; token identifies original sibling name, not a guarantee it remains ours.

Pin later CLI mapping now: target_exists/revision_not_found/path_denied semantic3;
invalid invocation ID handled by CLI2; native invalid semantic argument schema3;
underlying ledger mapping unchanged. Ordinary io/unsupported safe-publication
capability exit4 with details operation export. publication_uncertain uses io4,
message "Export may be complete; inspect the explicit target before retrying".
cleanup_incomplete uses export_incomplete exit4 and details
`{operation:"export",cleanup:"incomplete",location:<generated stage basename>}`;
message tells user to inspect this sibling name in their supplied target parent,
without implying it is safe to delete automatically. Missing target after prepub
failure is not assumed when an independent actor may have created it.

F2 will add a narrow optional response context so main's stdout-write failure after
successful export gives the same inspect-target guidance (operation stdout).
Default render/init/history output failure behavior stays unchanged. This is not
implemented in F1 and must not be claimed by its evidence. Allocation/encoding
failure in F2 after publication also needs uncertainty handling, never ordinary
prepublication-failure wording. No command/response changes in this unit.
