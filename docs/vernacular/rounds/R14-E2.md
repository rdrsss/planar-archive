## Search outcome and concrete contract

Fresh `/root/r14e2_search` completed read-only mapping. Existing format_file methods
own a single pinned verified snapshot and already supply owned head, page, revision,
event and request rows. No native format/schema/capture/Lua changes are needed.
`request_row.body_encoded` contains private intent paths and must never enter public
projection. Recorded interpretation decoding is pure and allows an unsupported
interpretation to fail this view without disabling page/request/state or raw export.

The following pins implement the existing ledger contract, without adding load:

- Outer response exactly `{version:1,kind:"history",ledger,active_revision,last_event,data}`.
  Every database ID is a canonical positive decimal string; absent IDs use `"none"`.
- Page data: `{selector:"page",events:[...],next_after?:<ID>}`. Default limit 50,
  explicit 1..100. Omitted cursor maps to native zero; explicit cursor must be a
  canonical positive decimal ID <= INT64_MAX. Omit next_after when no more events.
- Event summary: `{sequence,type,version,revision,request_id,actor,occurred_at,payload}`.
  Version is integer; revision/request absence is `"none"`. Payload is the exact
  structured public event schema from history_codec, not a quoted JSON string.
- Revision data: `{selector:"revision",revision:<metadata>,interpretation:<full value>,versions:<full value>}`.
  Metadata exactly `{id,parent,source,registry,stdlib,interpretation,versions,actor,accepted_at}`.
  The five record IDs remain strings. Decode stored records and historical values
  through existing record/interpretation codecs; no current stdlib/Lua invocation.
- Request data: `{selector:"request",result:<decoded saved load result>}`.
  Never project private body/body_reference/body_encoded or intent host arguments.
- State data: `{selector:"state",event:<summary>,state:{active_revision:<ID-or-none>},revision:<metadata-or-"none">}`.
  Resolve after-state from the verified event payload; attach its matching revision
  metadata, or none at initialization. Outer head/last_event remain current snapshot
  values even when inspecting earlier events. No interpretation decode is needed.
- CLI11 requires ledger and owns all parsing. Revision/request/at-event selectors
  mutually exclude one another and both paging options. Limit alone is legal.
  Required/duplicate/unknown/positional/equals syntax and noncanonical/zero/signed/
  overflow numeric arguments or selector conflicts are invocation exit 2. Unknown
  well-formed IDs are semantic exit 3. Root-only help remains the current pattern.
- Entire stdout including final LF is at most 16,777,216 bytes. Glaze encode uses
  maximum JSON bytes 16,777,215; append LF only after success. Output byte-limit
  refusal uses existing resource_limit exit 3 with details
  `{limit:"output_bytes",maximum:16777216}` and empty stdout. Preserve distinct
  depth/node refusal details; do not mislabel them as output byte failures.
- Use existing ledger_error for storage errors. Selector misses map to
  revision_not_found/event_not_found/request_not_found. Unsupported interpretation
  maps to unsupported_interpretation, exit 3. Malformed verified stored data maps
  ledger_corrupt, exit 4. Do not forward native messages, private paths or bytes.
  Allocation failure may retain existing safe empty-stderr exit 4 fallback.
