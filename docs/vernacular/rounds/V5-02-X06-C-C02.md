Layer 1 below was also incomplete (argument-dependent lookup, C03-R1). The text below is the C02 analysis as dispatched.

Three layers, strongest first, each stated for what it does and does not stop:

1. Language visibility. `ledger.acceptance` imports the seam privately, so a plain importer of `ledger.acceptance` cannot name
   any seam entity. This stops plain importers only.
2. Passkey (new). The seam is still importable by name by any target that has its module file, because `planar_rewrite_module`
   links DEPENDS as PUBLIC (`cmake/rewrite.cmake:23`) and 67 `src/cmd/planar` targets carry it in their link closure (C01-R2;
   probe C22 proved it). The passkey closes this at compile time: every exported entry point and constructor takes a key whose
   constructor is private and befriends only the embedded adapter and the `prepared_profile` adapter, so a named importer that
   is neither adapter cannot construct the key and fails to compile. This is the structural enforcement the C01 review
   asked about; it needs no partition of `ledger.acceptance` and no new runtime edge into the ledger variants.
3. Source-scan test (kept, second check). The R1 test scans `src/**/*.cpp(m)` and the private-import text. Its blind spots
   remain: sources outside `src/` and generated sources.

The link graph is unchanged (DEPENDS PUBLIC). Nothing in this round claims the link graph restricts reachability. Known limit
of the passkey: `friend` names the two adapter classes or functions, so any code added to those adapters is trusted, and the
seam still does not recheck that the values come from a real prepared object (storage verification remains the dynamic
defence). The opaque `prepared_profile` type and the I9 guard stay the authority for profile completion.

## Review outcome (2026-10-26)

Decision: **request-changes** ([review](V5-02-X06-C-C02-review.md)). Candidate identity verified unchanged since review: the
`git diff HEAD -- src` hash is `e9f10163...cb582` and the per-file hashes of `acceptance_seam.cppm`, `acceptance_seam.cpp`,
`profile_acceptance.cpp`, `profile_acceptance.t.cpp` and `r14c3b2-support/generate.py` equal the table above. Nothing is committed.

Findings:

- **R1 (blocking, product and records):** the passkey does not give compile-time exclusivity. The grant classes are `extern "C++"`
  forward declarations in the exported namespace, so any translation unit can define one and mint a `seam_key`; `seam_key` is
  trivially copyable, so `std::bit_cast` mints one as well. Three routes compile with exit 0 under the `planar_command_invocation`
  flags: f1 defines `seam_grant::test_probe`, f2 defines `seam_grant::embedded_adapter`, f3 uses `bit_cast`. The negative-compile
  probes missed them and no row covers "only the two adapters are friends". `seam_grant::test_probe` is also a third friend, against
  the operator decision. The seam doc comment and three records claim compile-time exclusivity. Raw logs:
  `tests/native/v5-02-x06-c-c02-evidence/review/raw/key-forge/`. Needs an operator decision plus either a structural fix or a
  recorded amendment, and corrected claims.
- **R2 (minor, records):** criterion 1 says the I-PK5 scan confines `seam_grant` to "five allowed files"; the test's allowed set
  (`profile_acceptance.t.cpp:1015-1016`) has four.
- **R3 (minor, records):** leftovers of C01-R4: the generate.py ownership extension is not named on the amendments line, and the
  blind spots of the criterion 1 amendment are described as "backed by the passkey"; restate once R1 is resolved.
- **R4 (minor, evidence):** the red-first snapshot hash `769c5a2c` covers tracked files only although the passkey stubs were in the
  untracked `acceptance_seam.cppm`, and `red/raw/build.log` shows no build. The C14 row was dispatched test-first but recorded
  `expectRed=false`; that departure is not stated.

Consequences: criteria 1 and 5 are not accepted as recorded; the "compile-time exclusivity" claim in this record, the C01 record's
authority analysis and X06-C row 9 is withdrawn pending the corrective. Other criteria (2-4, 6-8, V1-V6) stand as evidenced. The
operator decision on R1 (strengthen the structure so forging fails to compile, drop `test_probe`, or amend the claim to a
convention-level seam guarded by the scan) is required before dispatching the corrective. Next round: X06-C-C03.
