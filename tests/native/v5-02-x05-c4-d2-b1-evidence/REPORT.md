## Behavior and authority

The native overload takes an issued move-only original supplied-file token. It
walks physical parent components through the D1 narrow no-follow path (including
actual `..`), opens the selected leaf no-follow, verifies that actual FD, and only
then publishes a standalone input root. No content or directory membership is read.
Parent supplied-root admission/overlap is deliberately absent: registry colocation
is allowed while original observation and trusted selected-alias policy remains.
The profile facade issues the token only through its original private admission.
No getter, callback/provider, cloned receipt, reconstructed admission or admission
API change was added.

The root retains the same pending token through vector relocation and wrapper
moves/destruction. Plain initial reads resolve it before content allocation/read;
successful retention moves that handle itself into the captured entry. A matching
retained read checks the incoming identity and transfers the original pending
handle, never the replacement. Borrowed modes refuse before content. Captured
plain/cache/ceiling/seal/acceptance paths keep D2-A's original authority. A bound
session's terminal marker prevents fallback after failed read/publication or an
invalid moved pending token. Guards poison original shared state before error
adaptation; temporary descriptors close under RAII.

Unread inputs retain pending authority through seal and acceptance. Verification
reopens the physical parent, checks original parent identity and actual selected
leaf metadata, and never reads content merely to seal. The logical path remains
exactly input.json; sibling paths and tree traversal refuse before enumeration.
Read inputs retain ordinary immutable bytes and content verification. Trusted
profile content verification remains separate from shared metadata authority.

Existing metadata accounting charges each issuance for the 24-byte handle plus
32-byte possible native optional storage. A bound root retains that issued optional;
the transfer makes it empty before subsequent use. Native captured records retain
the existing 32-byte optional, bounded separately by the 10000-file ceiling. The
new root optional and marker add 32 bytes, giving the compiled root layout of
136 bytes; the marker fits existing padding. The session terminal marker fits
existing layout padding. The bound-root count is
bounded by charged token issuance under the existing 64 MiB admission metadata
