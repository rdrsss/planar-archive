# R15-A1-C01 invariant table (search stage, revision 4, 2026-11-01)

Companion of `DECISIONS.md` in this folder (D97 to D104 and the amended D43, D55, D56; script rules and record rule in its
opening). Authoritative. Revisions 1 to 3 are in `superseded-1/`, `superseded-2/` and `superseded-3/`. Revision 4 fixes the 11 plan-review gaps of revision 3 (wave order, final results, C31 and C61 mutants, prober overlay, C23 expectRed, C16 predicate, HALT-1 relabel, R5 wording, C36 mutant, C59 alignment, original-checker location; see DECISIONS.md opening). The earlier table
(`tests/native/v5-02-r15-a1-evidence/plan/INVARIANTS.md`, rows I1 to I70) stays as history (relabelled and given correction
notes by R1). Every check name from it is kept; C01 amends the body of some (section 2) and adds `CHK-C01-*` checks (section 1).

Docs-only round. "Mutant" is a textual defect in a scratch copy of the changed documents (delete the clause, make it
permissive, restore the old wording, respell); several mutants of one row are written `m1: ...; m2: ...` and each gets its own
id `<row id>-m<k>` and its own raw log. "Test" is a named scratch check in the repaired `ex_checks.py` (canonical copy in the
scratchpad, evidence copy `tests/native/v5-02-r15-a1-c01-evidence/red/ex_checks.py`, executed only from the scratchpad). There is
no TEST_CASE and no product build. Only the mutation-prober packages (PROBER wave 5, PROBER2 wave 7) apply mutants, in a scratch
git tree outside the checkout (DECISIONS, script rules item 3). A mutant is KILLED only when the named test fails and the run
output names that test; any other failing check does not count as the kill. Coders never mutate checkout files.

Phases. Core checks run in the default mode of the checker. Six AUDIT checks run only with `--audit`, because they audit files
other packages write later: C29 CHK-C01-sql-evidence-recorded, C30 CHK-C01-green-evidence, C31 CHK-C01-prober-evidence, C32
CHK-C01-record-closure, C33 CHK-C01-red-evidence, C61 CHK-C01-record-d81.

`expectRed` has a precise meaning. For a core row, true means: run against the pre-C01 candidate (the live checkout before PA and
PB edit it), with the repaired checker in default mode, the named test FAILS on assertions about the text or the SQL (never on
a missing file or a Python error); false means it passes there and guards existing behaviour (for a checker-repair row, the OLD
checker failed it on the candidate and the repaired one passes, and the mutant proves the repaired check can fail). Red FAIL set
of `red/red-run.txt` (default mode) = exactly the core rows with expectRed true: C1 to C4, C6 to C23, C39 to C43, C48, C57
(29 rows; C5, C24 to C28, C34 to C38, C44 to C47, C49 to C56 and C58 to C60 PASS). For an audit row, true means: in `--audit` mode on the same
snapshot it FAILS; absence messages ("lacks", "missing file") are allowed for the six audit rows only, and
`red/red-audit-run.txt` shows exactly those six FAIL.
