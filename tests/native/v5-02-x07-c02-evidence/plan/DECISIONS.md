## Root cause (code citations at HEAD)

- `profile_invocation::open_known_load` (`src/engine/runtime/runtime.cpp:5294`) admits the load ledger with `admission_file_role::ledger`.
- `capture_admission::implementation::check()` (`src/engine/capture/admission.cpp:259-285`) compares every file receipt with `same_file` (`admission.cpp:61-69`: device, inode, mode, size, mtime, ctime) twice: through the retained descriptor (`:264`) and through `fstatat` by name (`:265-270`). Every retained receipt (`retained_file_receipt::verify` `:530-540`, `retained_root_receipt::verify` `:579-590`, `capture_admission::verify` `:394-407`) calls `check()`.
- A winner commit changes the ledger's size, mtime and ctime, so the loser's later `check()` throws. Two sinks follow. (i) `prepare_load` phase 6 (`runtime.cpp:5921-5927`) and `open_known_load`'s tail verify (`:5319`) report `capture_changed` / `Captured external profile changed` (in the closed table, exit 3, wrong code). (ii) `prepared_profile::verify_native_receipts` (`runtime.cpp:5538-5551`) and `acceptance_capture::verify` (`src/engine/capture/native.cpp:939-948`) rewrite the failure to the non-table `capture_changed` / `Captured inputs changed during verification`, which `registration_failed` (`src/cmd/planar/response.cpp:263-271`, `closed_pairs` `:183`, `in_closed_pairs` `:249`) redacts to `internal` / `Invalid external profile protocol`, exit 4.
- The seam already orders the CAS before the final receipt verification: `src/engine/ledger/acceptance_seam.cpp:53` (`head->revision != data.expected_head`) precedes `:107` (`candidate.verify()`). Identity-of-ledger prelude check is `:28-29`. This ordering is unchanged and is not owned.
- The CLI call order in `src/cmd/planar/invocation.cpp`: `open_with_profile` (`:508`), anchor `after-factory-open` (`:511`), `prepare_load` (`:513`), anchor `after-prepare-load` (`:519`), `complete_acceptance` (`:521`).

Status legend: **CD** = contract-decided (clause cited); **RS** = decided in `docs/vernacular/remaining-steps-design.md` (question or section cited); **NWC** = "new within contract": a new engineering choice whose behaviour is bounded by cited contract clauses, not a product or authority choice; **OP** = operator decision recorded in the round record; **LIM** = recorded limit. No row is a NEW product or authority choice that needs an operator question (see "Operator questions" at the end).

Contract quotes used by the NWC rows:

- Ledger contract load step 3 (`ledger-contract.md` ~359-365): "Look up the request again: another writer may have committed during capture; exact body replay/conflict still precedes CAS."
- Step 4: "For an unknown request require expected head equal current active head ... A mismatch refuses `revision_conflict`, even if content equals the current head. No new request row survives refusal."
- Step 5: "Recheck retained filesystem capture receipts immediately before committing acceptance ... closure membership is determined by the captured declarations and references ... Necessary ancestor directory identities, selected file/root identities and normalized file modes remain checked ... A detected closure byte/mode/identity change refuses `capture_changed`."
- External-profile contract (`external-profile-contract.md:169`): "Ledger is native data". `profile-preparation-architecture.md:207-208`: "The ledger selector is native-only, used for initial selected-file alias checks".
