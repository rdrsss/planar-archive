`provenance_driver.py` additions:
- `run_provenance(config)` accepts optional `config["verify"]` (default `True`). When true the in-run `verify_readback`/`verify_absent_readback` loop runs (messages unchanged); when false it is skipped. The result gains `"verified": <bool>` (true only when the loop ran) and `"token_absent": <bool>` (true when `scan_for_tokens` over the retained provenance files and retained `*-history.stdout` files found none of the three bearer tokens).
- `scan_for_tokens(paths, tokens) -> bool`: True when none of the token strings occurs (as UTF-8 bytes) in any existing path; a missing path is skipped; empty `tokens` raises `AcceptError("provenance read-back: no token was supplied to scan for")`.
- `readback_manifest(result) -> dict`: path-free; EXACT top-level keys `version` (1), `facts`, `claim`, `takeover`, `nofile`, `checks`. `facts` = `{accepted_revision, baseline_ref, baseline_sha256, candidate_sha256, candidate_size (int), driver_version}`. `claim`/`takeover`/`nofile` = `{event_id, run_id, provenance}` with `provenance` = `result[<section>]["readback"]`. `checks` = `{token_absent_in_run_dir, verified, claim:{...}, takeover:{...}, nofile:{...}}` with booleans `native_ten_keys`, `preferences_unknown`, `generation_expected` ("1","2","3"), and for claim and takeover `document_matches_supplied`. No `env`, `provenance_path`, `argv`, path or token.

`checkpoint_driver.py` (new):
- `build_checkpoint(*, progress, next_step, unresolved, files) -> dict` with exactly `progress, next, unresolved, files`.
- `build_observations(checkpoint) -> dict` = `{"version":1,"checks":[],"findings":[],"checkpoint":checkpoint}`.
- `validate_checkpoint(cp)`: raises `AcceptError("checkpoint: <path>: <reason>")` per `render-contract.md:219-226`: exact keys; `progress`, `next`, `unresolved` `str` of 0 to 2,048 UTF-8 bytes without NUL; `files` a list of 0 to 32 distinct `str` relative paths (no NUL, not absolute, no `..`); canonical JSON (`json.dumps(sort_keys=True, separators=(",",":"), ensure_ascii=False)`) at most 8,192 bytes. Empty strings and an empty files list are ACCEPTED. Reasons: `must be at most 2048 UTF-8 bytes`, `must not contain NUL`, `is missing`, `is an unknown key`, `must be a list of at most 32 distinct relative paths`, `canonical JSON exceeds 8192 bytes`.
- `verify_effect(before, after, since=None)`: `before` and `after` are dicts `{work_fp, render_digest, state, markdown, sections, omitted}` (`sections` = packet manifest rows `{id,included,bytes}`, `omitted` = IDs in the packet's omission section); `since` is the WHOLE decoded `preview --since` JSON (key `since` as above, top-level `work_fp`/`render_digest` as the current side). Raises `AcceptError` beginning `checkpoint effect:` with the FIRST failing clause in this order: `work_fp changed`; `state changed`; `render digest did not change`; `packet lacks a checkpoint section` (absent `## checkpoint` with no budget explanation; with the manifest row `checkpoint` not included and `checkpoint` in `omitted` it raises `checkpoint fixture limit: checkpoint section omitted by budget` instead); and, only when `since` is given, `since reports material changes`; `since lacks an added checkpoint section`; `since does not match the after packet`. Returns `None` when all hold.
- `checkpoint_manifest(result) -> dict`: see row C9.
- `run_checkpoint(config)`: config keys of `fault_driver._Scenario` (candidate, scratch, raw_root, home, ledger, counter, repo, tamper) plus optional `verify` (default True), forced `mode` cmake, `check_mode` sleep, `base` plain; `tamper` key `observations_path == "missing"` points checkpoint #1 at a missing file. Order: claim; `before` (fresh preview); checkpoint #1 (text T1); `after1` (preview); checkpoint #2 (text T2 != T1); `after2` (preview); `since` (`preview --since <claim render digest>`, taken after checkpoint #2); `control` (preview, no change). Result keys: `scenario` `"a03-checkpoint"`, `mode`, `candidate {sha256,size}`, `env {HOME,PLANAR_DB}` (copied from `scenario.env`), `ledger`, `facts`, `steps`, `claim {request_id, run_id, work_fp, render_digest, state}`, `before`, `checkpoint1`/`checkpoint2 {request_id, exit, argv (with `<run-token>`), observations_path, observations_sha256, observations (decoded), event_id (from `checkpoint_v1` `checkpoint.event`), text}`, `after1`, `after2`, `since`, `control`, `verified`, `token_absent`. A refused checkpoint raises `AcceptError("product defect: checkpoint refused a contract-valid observations file (exit N, code C)")` and writes `raw_root/ABORTED.json`; a checkpoint not in the legal actions raises `product defect: checkpoint is not a legal action in the captured guidance (...)`; the budget-omission case raises `checkpoint fixture limit:` (not a product defect).

`run_acceptance.py` (I2, additions only): subcommand `checkpoint` (`cmd_checkpoint`, `run_live` default name `a03-checkpoint`, same arguments as `provenance`) calling `checkpoint_driver.run_checkpoint`, then writing `a03-readback.json` (via `checkpoint_manifest`) next to `result.json`; `cmd_provenance` additionally writes `a34-readback.json` (via `provenance_driver.readback_manifest`). Both use `write_new_json`. No existing line is removed or changed; neither parser gains an option.
