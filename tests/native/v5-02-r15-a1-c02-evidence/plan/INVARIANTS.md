# R15-A1-C02 invariant table (search stage, revision 4, 2026-11-06; revision 3 is in `superseded-3/`, revision 2 in `superseded-2/`, revision 1 in `superseded-1/`)

Companion of `DECISIONS.md` in this folder. Authoritative for the round. Docs-only round: "mutant" is a textual defect in a scratch copy
(a standalone clone of HEAD overlaid with the working tree and the three evidence trees, outside the checkout); "test" is a named check in
the C02 checker copy (`green/ex_checks-c02.py`, derived from `red/ex_checks.py`, which stays untouched; run only from the cmp-identical
scratchpad copy `<scratchpad>/c02/ex_checks-c02.py`, D5, D36). There is no TEST_CASE and no product build. Only the mutation-prober packages
(PROBE, PROBE2) apply mutants. A mutant is KILLED only when (a) the exit code of the checker command is non-zero, (b) a `FAIL` line names the row's
test, and (c) the row's test is a `PASS` line of the baseline log named for the row in the baseline map of section 6 (BD, BA or BC, D28), or of the control run of the same source row where the row says so (D38); anything else is SURVIVED (a missing runner,
empty output or a scratch tree equal to pristine is "not run", never killed). A control (id `<row>-c<k>`, D38) is a run that must PASS; it is never a mutant and never counted in killed, survived or not-run totals.

`expectRed` true: in the pre-fix tree (before DOC and REC1 edit it, with the C02 checker copy from CHK) the named check FAILS on an assertion about
text or about a file that this round is to write (absence messages are allowed only for the rows named in D34). `expectRed` false: the check passes there
and guards existing behaviour; the prober proves it can fail.

Packages and waves (exclusive file ownership per wave): CHK 1 (test); DOC 2 (impl, contract line 520); REC1 2 (impl, record incl. the first-draft staging list and the `Evidence by pointer` bullet, README, RED.md); PROBE 3 (test,
main section); REC2 4 (impl, record D81, identity block, N5 basis); GREEN 5 (test, provisional logs); REC3 6 (impl, record Final results, staging list,
C02 acceptance status); GREENB 7 (test, refresh of the provisional logs after REC3); PROBE2 8 (test, closing section, audit baselines); CLOSE 9 (impl, record and README last edits); GREEN2 10 (test, final logs, audit-final, audit-verify, redaction-final). The red set
at the end of wave 1 (pre-fix tree): default mode 12 FAIL (N1 to N7, N11, N12, N13, N14, N15), audit mode 19 FAIL (those plus AU-C29, AU-C30, AU-C31,
AU-C32, AU-C61, N9, N17); everything else PASS.

## 6. Log and verdict rules (all prober and green packages)

1. Every log is produced by running the command and reading the exit code directly (never through a pipe), then masked with the cmp-identical `mask_log.py` (D27). Scripts run only from scratchpad copies (D5).
2. Baselines first (D28, D37): PROBE writes BD `probes/raw/baseline-c02-default.log` before any mutant; PROBE2 writes BA `probes/raw/baseline-c02-audit.log` (audit mode with `--pending closing --pending acceptance`) before any audit mutant, and BC `probes/raw/baseline-c02-audit-closed.log` (audit mode with `--pending acceptance` only) after every other mutant and the closing section of `PROBES.md` exist. A baseline with any FAIL stops the package.
3. Per mutant: restore the working clone from pristine, apply the mutation chained with `&&`, verify `diff -r` is non-empty (else `not run`), run with `perl -e 'alarm 600; exec @ARGV'`, record the log, decide the verdict from the unmasked output, then mask the log. A control: restore, apply the stated neutral edit (or none), run, require exit 0 and the test PASS, log with the line `control: yes`, verdict `control-ok`.
4. Survivors (D29): fix the check body (never the contract or the record), keep the first log as `<id>.survived-1.log`, re-probe every mutant of the touched check and of rows sharing it; tsv and table carry the final verdict, Survivors keeps the first verdict, totals count final verdicts. AU-C30 mutants are probed before any repair; after a repair PROBE2 regenerates a scratch `checks.txt` in the clone and retakes BA (D28).
5. GREEN2 writes every audit output to a scratch file, masks it and installs it atomically; `redaction-c02.txt` is never appended to after masking (D46).
6. Lesson 1: coders never mutate; each new check's report names the mutant each test should kill.
