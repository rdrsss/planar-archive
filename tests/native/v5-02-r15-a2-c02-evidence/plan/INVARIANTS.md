is a named check of `tests/native/v5-02-r15-a2-evidence/checks/contract_checks.py` (file for every row below unless the row
says "workflow row"), run only from a scratch copy by the mutation prober. "Mutant" is a text edit of ONE scratch copy of
the named contract file, applied by the prober only, outside the checkout, only if the replace count is exactly 1
(counts verified on the final bytes). File keys: `EC` = `docs/vernacular/execution-contract.md`,
`CC` = `docs/vernacular/command-contract.md`, `LG` = `docs/vernacular/ledger-contract.md`. `OLD` and `NEW` are exact
byte strings; a `\n` never occurs inside them. Where OLD must be located by line, the line is given and the replace is
limited to that line.

Checkers and expected verdicts (C02-D12, C02-D14). Every row of sections A, B and C is run by P3 against BOTH checkers:
`probes/checker-attempt-2/` (the pre-fix copy, column "attempt-2") and the attempt-3 checker (column "attempt-3").
Each row states the EXPECTED verdict for each. Verdict vocabulary: KILLED (exit not 0 and a `FAIL` line names the check in
the "test" column), KILLED-OTHER (exit not 0 but only another check fails; counted as a survivor of the named check),
SURVIVED (exit 0 or the named check passes), EMPTY (empty diff), PASS (unmutated control: the named checks print PASS),
NOT RUN (no SUMMARY line; never KILLED), n/a (not applicable). An observed verdict that differs from the expected one is
reported as a deviation, never relabelled; a deviation in "attempt-3" re-dispatches P1 (and then C02-D26 voids P2 and every P3 attempt-3 run: they are re-run on the changed checker); a deviation in "attempt-2" is
stated as weakened red evidence for that row.

"expectRed" has ONE meaning in this table: true = the attempt-2 checker does NOT kill the mutant with the named check
(SURVIVED or KILLED-OTHER), so the row is red-first evidence for new checker code, and the attempt-3 checker must kill it.
false = guard of behaviour the attempt-2 checker already has (expected KILLED on both), an unmutated control, or a workflow
row. The K rows aimed at new branches (expectRed true) are those with attempt-2 SURVIVED or KILLED-OTHER. A KILLED-OTHER attempt-2 verdict lists EVERY other check that kills the mutant (revision 3); P3 flags a deviation if the attempt-2 killer set differs from the one stated, in either direction.

Checker identity (C02-D26, row A23): P2, P3 and P4 record verbatim `shasum -a 256` of the scratch `contract_checks.py` and `fixtures/*` they ran; P4 and P6 assert all recorded sets equal the checkout checker.

Packages: P1 checker, P2 red attempt 3, P3 mutation prober, P4 docs evidence finisher, P5 record sync, P6 final-state
finisher (plus the coordinator steps C02-D27 and C02-D29). No row requires a new public field or fault hook: no `src` change exists.
