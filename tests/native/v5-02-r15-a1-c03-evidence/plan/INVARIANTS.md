Docs-only round: a "mutant" is a textual defect in a scratch copy (a standalone clone of HEAD
overlaid with the working tree and the three evidence trees, outside the checkout, DECISIONS D3); a "test" is a named check of the C02 checker (`E/green/ex_checks-c02.py`, run
only from the cmp-identical scratch copy `<scratchpad>/c03/ex_checks-c02.py`) or a named record assertion `ASSERT-C03-*` of the stdlib script `E/green/record_asserts_c03.py` (DECISIONS D12), or the preflight script `rec_preflight_c03.py` (C3-PF). There is no TEST_CASE and no product
build. Only the prober packages PRA, PRB, FIN1 and FIN2 apply defects, and only in scratch copies; coders and repair coders never mutate, stash, revert or
experiment with checkout files. A mutant is KILLED only under the rules of DECISIONS D6 and D32; a control (id `<row>-c<k>`) is a run that must PASS, is never counted in killed, survived
or not-run totals and has verdict `control-ok`.
