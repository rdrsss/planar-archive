## Native behavior and ownership

The generic downward `format_read_guard : read_guard` binds the actual no-follow
held descriptor before the first raw header pread. The separate
`open_existing_gated(path, guard)` is read-only and passes the same guard object
to the approved per-connection SQLite VFS. No capture/runtime dependency enters
ledger modules. The format owner checks the original guard before and after every
native read, including cached SQL success, and retains first typed gate status
without allocating. It also checks SQLite's sticky status before publishing the
verified owner or a result. Ordinary ungated behavior and writable transition
remain available through their unchanged opener. Cached `metadata()` stays
accessible after failure and is explicitly not authorization.

`extension_invocation::prepare_history()` returns only success or the native
variant of registration/profile, format and history-read errors. It privately
retains the history envelope containing ledger identity, last_event and selector
results. No mutable returned value becomes service authority. Only the existing
private prepared selector, host path and original moved profile_capture are used;
there is no caller SQL, query, replacement capture or recapture.

The adapter verifies the exact original `extension.ledger` receipt against the
actual descriptor before header content access, duplicates that descriptor without
reopening, and verifies original receipts plus the duplicate at every gate. The
borrow of capture is strictly inside synchronous preparation. All format,
statement, transaction and connection owners leave the inner scope before the
post-read original receipt seal, on success, typed failure and allocation refusal.
The duplicate remains owned until the final verifier use, then closes before
return. No guard survives in the retained history. No Lua runs in this helper;
read-capability handler execution still refuses.

Preparation is once-only. Moved, failed, unadmitted and repeated calls refuse;
failures poison later admission/execution/verification. First native errors remain
retained across retries and moves. Original profile gate errors outrank generic
SQL or query errors, including an allocation refusal while copying the final
failed-capture diagnostic. Resource and protocol refusals remain distinct. Missing
revision/request/event errors remain typed. No new recorded profile interpretation
or effective-provenance history reader is added.

The runtime depends downward on the existing history-read module, which depends
on format and pure codecs; no cycle is added. Existing generated runtime-test,
shapes, command/load/closure and CLI variants receive the same dependency through
their existing CMake declarations. Only the two authorized CLI DEPENDS clauses
are changed outside engine CMake. This foundation does not compose existing
VM/capture/native storage allocation meters; X06 still owns shared accounting.
No new ledger quota or process RSS claim is introduced.
