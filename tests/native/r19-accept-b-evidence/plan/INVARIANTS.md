## Stub contract (PKG-T writes it; PKG-I replaces it)

Stub bodies: `build_document` returns `{}`; `normalize_document` returns its argument; `tree_sha256` returns `""`; the others raise `accept_lib.AcceptError("not implemented")`.

Red-first shape (D20, D30): live classes build their shared run in `setUpClass` inside try/except that stores the exception text in `cls.error`; each live test starts with `if self.error: self.fail(self.error)`. Offline tests that must accept wrap the call (`try ... except AcceptError as e: self.fail(str(e))`). CLI tests (I18, I19) never use `assertIn`/`assertEqual` on subprocess text and never put `proc.stderr` or `proc.stdout` in a message: they test `if <condition>: self.fail("<fixed text without 'error: '>")`. So every new test is one FAIL; `red/RED.md` lists each with FAIL and reason, runs `accept_lib.validate_red_record` on the log and states no ERROR comes from an import.

## Real-contract signatures (tests are written against exactly these)
- `UNKNOWN = {"status": "unknown"}`; `DRIVER_NAME = "r19-accept-support/provenance_driver.py"`.
- `build_document(*, driver_version, trial_id, view_id, settings) -> dict`: `settings` dict name->string; returns `{version:1, driver:{name:DRIVER_NAME, version}, trial:{id}, view:{id}, model:{requested:U,actual:U}, session:{requested:U,actual:U}, settings:[{name,value}...]}` sorted by `name.encode("utf-8")`; model/session leaves are fresh copies of `UNKNOWN`.
- `validate_document(doc)`: raises `AcceptError("provenance document: <path>: <reason>")` (dotted path; a missing key names its own path; an unknown key names itself); order: top-level key set, version, then leaves in document order. Rules (`execution-contract.md:1108-1112`): exact keys `version,driver,trial,view,model,session,settings`; `version == 1`; every leaf a str of 1..1024 UTF-8 bytes without NUL or exactly `{"status":"unknown"}`; settings names str leaves (never unknown), unique; at most 32 settings. Returns None when valid.
- `normalize_document(doc) -> dict`: deep copy, settings sorted by unsigned name bytes, input not mutated.
- `verify_readback(expansion, document, *, token, native_expect)`: `expansion` = full `history --event N` JSON; reads `data.execution.provenance`; raises `AcceptError` starting `provenance read-back:` with the first failing clause in this order: `authority is <x>, expected driver_assertion_unverified`; `driver.id is none`; `document differs at <dotted path>` (compared with `normalize_document(document)`); `native lacks <key>` (exactly the ten keys `base_label, generation, job, ledger, preferences, render_fp, revision, role, source, work_fp`); `native.preferences.<model|session> is not unknown`; `native.<key> is <actual>, expected <expected>` per `native_expect` pair (dotted paths); `bearer token present` (token anywhere in `json.dumps(expansion, sort_keys=True)`, last).
- `verify_absent_readback(expansion, *, token, native_expect)`: same envelope, requires `driver.authority == "none"` (message `authority is <x>, expected none`), `driver.id == "none"` (`driver.id is <x>, expected none`), `driver.document` exactly the all-unknown form `{version:1,driver:{name:U,version:U},trial:{id:U},view:{id:U},model:{requested:U,actual:U},session:{requested:U,actual:U},settings:[]}` (`document differs at <path>`), then the same native, preferences, native_expect and token clauses.
- `require_accepted(step, verb)`: `step = {"exit": int, "stderr": str}`; None for exit 0 else `AcceptError("product defect: <verb> refused a contract-valid provenance document (exit <n>, code <code>)")`, `<code>` = `error.code` of JSON stderr or `unparsed`.
- `tree_sha256(root) -> str`: hex sha256 over, for each regular file sorted by posix relative path bytes, `relpath + "\0" + sha256hex(bytes) + "\n"`.
- `run_provenance(config) -> dict`: config as `run_live` builds it plus `mode:"cmake"`, `check_mode:"sleep"`, `base:"plain"`, `tamper:{}` (tamper `provenance_path:"missing"` makes the claim use a nonexistent path). Subclass `fault_driver._Scenario` (D2). Sequence: `prepare()`, init `--workspace-id engine_cmake`, write `combined.lua` = `job_max1`, load, activate, claim `--provenance` (`claim-builder-1`, actor `builder-session`, point `claim_builder_1`) then `require_accepted(step,"claim")`, takeover `--provenance` (`takeover-1`, actor `replacement-session`, `--run-id` claim run) then `require_accepted(step,"takeover")`, final takeover WITHOUT `--provenance` (`takeover-2`, actor `builder-session`, `--run-id` takeover-1's run) then `require_accepted(step,"takeover")`, then fresh-process `history --limit 100` plus `history --event N` for each of the three events found by type and request id. Result keys: `scenario:"a34-provenance"`, `mode:"cmake"`, `candidate:{sha256,size}`, `env:{HOME,PLANAR_DB}` (copied from `scenario.env`, the env actually given to every child process, never from config or `os.environ`), `ledger`, `facts:{accepted_revision,baseline_ref,baseline_sha256,candidate_sha256,candidate_size}`, `steps:[{index,verb,argv,exit}]`, `claim` and `takeover`: `{request_id, exit, argv, provenance_path, provenance_sha256, document, event_id, run_id, readback}` (`takeover` adds `previous_run`), `nofile`: `{request_id, exit, argv, event_id, run_id, previous_run, readback}` (argv has no `--provenance`), `takeover_applicable: true`. On abort write `raw_root/ABORTED.json` exactly as `fault_driver.run_scenario` does (`fault_driver.py:1155-1167`) and re-raise; no later argv file exists.
- Documents: claim `driver_phase=claim`, takeover `driver_phase=takeover`; same trial `r19-accept-b-a34-minimal`, view `source`; settings `accepted_revision`, `baseline_ref` (`58128234:src/engine`), `baseline_sha256`, `candidate_sha256`, `candidate_size`, `driver_phase`; `driver.version` = first 12 hex of sha256 of `provenance_driver.py`.
