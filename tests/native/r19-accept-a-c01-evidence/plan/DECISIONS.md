## Diagnosis (drives scope; reproduced read-only on a scratch copy of the defect ledger)

`history --event 6` on the defect ledger exits 4 `Unsupported trusted structural value`. The refusal is the structural
consistency check at runtime.cpp:208-213 (a node whose `boolean` flag is set while `kind != boolean`, or whose
`integer` is nonzero while `kind != integer`). That check is contract-correct and stays. The producer is
`src/engine/ledger/storage.cpp:1740-1745` in `history_rows` (called by `supplementary_execution`, storage.cpp:1756-1850,
for check_recorded evidence): for column kinds `'n'` (`duration_ms`, `output_bytes`) and `'b'` (`output_truncated`,
columns at storage.cpp:1809-1811) it sets BOTH `node.integer = **raw` and `node.boolean = **raw != 0`. A nonzero
`output_bytes` (503, 160 in the defect ledger) gives an integer node with `boolean = true`, refused at runtime.
Existing test execution.t.cpp:3955-3960 only counts items with zero values, so it never saw the defect.
Pre-fix behaviour per kind: integer nodes carry the exact integer already (`node.integer = **raw`) plus a wrongly set
boolean when nonzero; boolean nodes carry the right boolean plus a wrongly set integer of 1 when true. A stored 0 flag
therefore already reads `boolean=false`, `integer=0` on the unfixed source (this is why H3 is expectRed=false).
